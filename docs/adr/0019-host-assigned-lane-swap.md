# Riders pick their own bike; the host binds them with a one-keystroke lane swap before the countdown

**Status:** accepted — resolves [issue #35](https://github.com/birdman7260/roller-rumble/issues/35) on the [walk-up event map (#30)](https://github.com/birdman7260/roller-rumble/issues/30), and depends on the hardware findings in [#32](https://github.com/birdman7260/roller-rumble/issues/32)

At a walk-up event nobody is assigned a bike — solo or head-to-head, riders mount whichever roller they like. With two racers on two bikes, **rotation ticks alone can never identify who is who**: both rollers just produce ticks, so something outside the tick stream has to supply the binding. [#32](https://github.com/birdman7260/roller-rumble/issues/32) established that our box cannot supply it before its own GO — `basic_msg` reads no sensor pin outside `if (raceStarted)` and uses no interrupts, so the rollers are electrically invisible and a pre-`g` "spin to claim" gesture is unbuildable on our hardware.

We decided the binding stays **host-assigned, with a fast correction**: the host sets the lineup as they always have, and a **`lane swap`** — one keystroke, `S`, or a button in the race tray — moves every racer to the other bike once the riders have actually mounted. Head-to-head exchanges the pair; solo moves the lone rider across. The swap is allowed while the race is `scheduled` or `staging` and refused from `countdown` on, where the box may already be armed against the old lane map and an active race has ticks banked per lane; the host resets the race to staged for that, which is the path that already exists for changing a race mid-flight. Because the correction is the operator's either way, it is **not gated on `event kind`** — a standard league night has the same hazard and gets the same key.

The load-bearing consequence: **a solo racer is staged on a real bike**. `lane` names which roller a racer's ticks come off, so `lane: "solo"` — a lane that names no bike — was the reason free bike choice was broken even for one rider: under a `left,right` `lane map` a solo racer matched no port and their ticks landed nowhere, and the positional fallback pinned them to port 0 regardless of which bike they were on. Solo races now stage on `left`, the swap moves them to `right`, and "solo" becomes purely a presentation concern — the projector centers a single card because there is one rider, not because of a lane id.

## Considered Options

**How a racer is bound to a bike**

- **Host-assigned with a fast correction (chosen).** Cheapest, works on any firmware, no change to `g` timing, no new hardware risk, and there is already precedent for a flip primitive (`raceDisplayLaneColorsFlipped`). The map's staffing constraint pays for it: one dedicated operator whose only job is running the app, for whom a keystroke between staging and start is affordable. Its real cost is that the operator must _notice_ — a missed swap crowns the wrong winner on a public screen.
- **Claim window after an early `g` (rejected).** [#32](https://github.com/birdman7260/roller-rumble/issues/32)'s find: the box's GO and the app's GO are separate events, and after `g` the box streams per-lane ticks unconditionally, so arming early turns that stream into a visible "spin to claim" phase. Self-evident to a crowd and the most nearly automatic option. Rejected for now on risk, not merit: it is untested on hardware (tolerance for a long arming period is unknown), it needs `progress` to stop unconditionally implying GO (`opensprints-session.ts`), and aborting inside the first ~4s is unsafe because `basic_msg`'s `s` clears `raceStarted` but not `raceStarting`. It remains the upgrade path — this ADR does not close it.
- **Bind after GO from the live stream (rejected).** Lanes start unnamed and bind on first ticks. Needs no `g` retiming and no abort hazard, but costs a few seconds of anonymous lanes at the start of _every_ race, including league nights where the lineup was never in doubt.
- **Correct after the fact (rejected).** Robust — attribution is repaired before results commit — but the crowd has already watched the wrong names race.

**How a solo racer's lane is represented**

- **A real `left`/`right` lane (chosen).** One meaning for `lane` everywhere: the roller the ticks come off. The `lane map` needs no `solo` entry, and the swap has somewhere to go for a lone rider.
- **Keep `lane: "solo"` (rejected).** Smaller blast radius, but keeps two ways to say "this rider is on the left bike" and leaves the lane map needing a `solo` entry that means "wherever the one rider is" — which is exactly the thing the hardware cannot tell us.

## Consequences

- **Ports resolve by lane, never by lineup position.** `OpenSprintsSession`'s positional fallback is replaced by a default `left,right` assignment (`DEFAULT_SENSOR_LANE_ASSIGNMENTS`), so a swap actually reroutes ticks even with no `lane map` configured. Head-to-head behaviour is unchanged — races stage left-then-right and `swapParticipantLanes` re-sorts to keep that order — while a solo racer on the right bike is now heard on port 1 instead of being pinned to port 0.
- **A race staged before this change carries `lane: "solo"`.** `oppositeBikeLane` sends it to the right bike, and the default lane map rides it on the left port, so an in-flight legacy race still reports. An operator's own `lane map` is taken literally: it says where they put the ports, so a `solo` entry there still means what it always did.
- **The simulator needs no change and exercises the whole control.** It has no physical bikes and builds its lane profiles from the participants it is handed at `beginRace`, which runs at activation — after any swap — so a swapped rider simply appears on the other lane. Its per-rider cadence bias is keyed to lineup position (`84 + index * 6`), so a swap also hands over that bias; the profiles are randomised anyway, so this is noise rather than behaviour, but it does mean the simulator is not a way to test that a _specific_ rider's numbers followed them.
- **On `basic_msg`, the swap never reaches the box.** It only re-points the app's port→racer map, which is the whole reason it is safe to do late: no command is sent, nothing is re-armed, and the box has not been told a race exists yet.
- **Lane colour follows the bike, on the live display and the results overlay alike.** `getLaneColor` now takes a lane instead of a lineup index. For a head-to-head race the two are the same answer, since the lineup is always ordered left-then-right; for a solo racer — always slot zero — the lane is the only thing that can move, so keying on it is what makes a solo swap visible at all. The projector therefore needs the lane per rider, which `buildParticipantEntries` now carries as `ProjectorParticipantEntry`. "Solo Run" on the winner card comes from the participant count, not from a lane id.
- **The race tray spells out the lineup per bike.** A swap is only checkable if the operator can compare what the app believes against the riders in front of them, so the summary lists "Left bike: … • Right bike: …".
- **`S` is the first bare-letter shortcut on the admin surface.** It is guarded against modifiers and against firing from inside any input, select, textarea, or contenteditable region; a second shortcut should reuse `isShortcutKeystroke` rather than re-derive the guard.
